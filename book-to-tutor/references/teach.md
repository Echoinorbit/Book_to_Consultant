# 讲解、动画与回讲

## 回答与出处

从问题找到书籍版本、小节及共享概念，核对原页，尤其注意公式下标、代码、图注和限定条件。对话里先解决读者问的那一步。对照多本书时分别给依据。书里没有的例子标为“导师自拟”；使用外部资料时标出来源链接。

聊天中的链接要能从当前客户端直接点开。链接标签说明目标，例如“看图 5.9 的代码与下一页图注”“播放两轮分块计算”。在 Obsidian 笔记内用实际相对路径或可解析的内部链接，在聊天里按所在客户端的格式输出本地绝对路径或已支持的 Obsidian URI。路径含空格时正确引用，URI 中的路径参数按要求编码。先确认文件存在；实际打开材料，检查显示的起页和播放效果。不要把只在笔记内有意义的双链直接贴成聊天答案。

PDF 阅读器支持页锚时，链接到 `#page=N` 的图体首页。若客户端丢失页锚，或图体与图注跨页，生成本地原页视图。它直接展示指定页的真实渲染，并附逐页跳回原 PDF 的链接。

```text
python scripts/source_view.py --pdf "本书原件.pdf" --start 250 --end 251 --out-dir "书目录/材料" --title "图 5.9 · 代码与图注"
```

将命令返回的实际 HTML 路径作为聊天链接。原页视图属于读者私有库，只为所问的具体材料生成。页序随版本和文件变化，每次先核对。

## 制作可直接播放的演示

数据流、状态变化、时间顺序优先用二维；观察角度影响理解时用三维。演示展示完整过程，读者可暂停和重播。无需中途作答；等读者看完、发起讨论后再追问。演示内容应与当前问题一一对应：说明起始状态、每个变化的原因及最后结果。

针对分块矩阵乘法的共享内存复用与同步，可将 [原创二维演示](../assets/tiled-matmul.html) 复制到当前书的材料目录，保留已存在的读者版本。它展示简化的教学模型，配合原书页视图使用。对其他机制，按实际例子制作自包含 HTML，使用本地可用的浏览器运行。避免外部 CDN 使离线演示失效。链接前打开并走完整次播放，确认最后一帧、重播和说明正确；在笔记旁留一张能解释关键变化的静帧或分步图。

## 主动回讲与产出

读者说“我来讲讲”时切换角色。先听完整解释，允许读者用自己的词。选择一个关键因果或前提，例如“如果下一轮已经开始覆盖共享内存，谁可能还需要上一轮的数据？”等回答后再回到对应动画阶段或原页，具体指出讲通和需要修正的部分。

读者想把新理解留下时，展示拟存原话及笔记位置，得到同意再写。可把同一生产任务的一个小变式留作下次自测，答案折叠。复习以读者节奏为准。
