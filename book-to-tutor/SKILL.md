# Book to Tutor

## 找到读者的库

从本 skill 的目录定位脚本和资源。对话中已明确的库路径可直接使用；否则运行 `python scripts/vault.py` 查找上次选择。首次使用时问读者「你的 Obsidian 库文件夹在哪里？」得到已有目录后用 `python scripts/vault.py --set "库目录"` 保存。要切库时更新这个选择。书、进度、笔记和演示写进读者选定的库。默认用中文教学，英文术语和代码标识符保留原样。

## 根据读者的请求行动

- **导入整本或继续上次导入**：读 [整书导入与多书融合](references/import.md)。书籍首页及覆盖清单是工作的起点。逐节阅读、撰写、链接并核查；每节的六问见下。中断后从未完成部分继续。仅在完成覆盖检查和内容抽查后报告整书入库，给出能点开的书籍首页。
- **自由提问**：读 [教学与可点击材料](references/teach.md)。允许从任一章发问。先回答当前问题，回查版本、原页和相关章节，再把可直接打开的来源或演示链接放在对应解释旁。资料欠缺时指出具体缺口，区分作者主张、导师推断和外部来源。
- **读者主动回讲**：让读者先讲完，再挑一个能揭示理解的条件变化追问。读者中途查一个词时，直接解答。想保存心得时，给出要保存的原句和落点，获得同意后再写入。

## 每节都回答的六问

1. **生产现场遇到了什么问题？** 写清业务、承担任务的人、能观察到的现象和影响。原书案例可核实就标明出处；自行构造的案例标为“生产场景示例”。对于基础数学或概念，找到真实的使用任务，如性能分析、评审、选型或排错。保留尚待验证的假设。
2. **本节解决其中哪一部分？** 把现场现象收窄到本节知识能够解释、测量或改变的环节。
3. **机制怎样运作？** 用因果关系讲清过程，必要时写出关键变量、步骤和数据流。
4. **哪些条件重要？** 区分正确性所需的条件、影响性能的条件，并给出适用边界。
5. **哪个例子能让我看懂？** 选一个能跟着推演的例子。关联原书的节、图、公式、代码或对应页；自拟算例标出身份。
6. **回到同一生产现场，我能完成什么工作？** 指出可执行的动作、可交付的成果、验证结果的证据。遇到性能问题，可以交付一份支持保留原实现的测量报告。不要虚构观测值或改进幅度。

章节笔记沿用书的论证顺序。概念笔记可跨书综合。维护既有笔记时保留人的原话及手工修改，按来源更新贡献。技能自带示例演示的适用范围是共享内存分块矩阵乘法；其他概念按实际教学需要制作。
